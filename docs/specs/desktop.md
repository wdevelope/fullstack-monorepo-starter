# 명세: 데스크톱 세션과 IPC 보안

- **상태:** 완료
- **ID 접두:** DESK
- **코드 경로:** `apps/desktop/src/main/`, `apps/desktop/src/preload/`, `apps/desktop/src/shared/`, `apps/desktop/src/renderer/lib/`
- **승인:** 2026-11-25

## 목적

Electron 앱에서 세션과 네트워크를 메인 프로세스만 다루게 한다. 렌더러(화면)가 XSS 같은 이유로 뚫려도 토큰을 읽거나 임의의 API를 부르거나 다른 페이지를 열 수 없게 하는 것이 목표다. 인증 규칙 자체는 [auth.md](auth.md), 알림 스트림은 [notifications.md](notifications.md)를 따른다.

## 규칙

1. 렌더러는 네트워크와 토큰이 없다. 모든 API 호출은 `window.desktop.rpc`로 메인에 부탁하고, 메인이 `@starter/api-client`(`clientKind: "native"`)로 보낸다.
2. `rpc`는 허용 목록에 있는 절차만 전달한다. 세션을 만들거나 바꾸는 절차(`auth.signup`·`login`·`refresh`·`logout`)와 `notifications.stream`은 `rpc`로 부를 수 없다. 로그인·가입·로그아웃은 전용 브리지 메서드로만 하고, 사용자 정보만 돌려준다(토큰은 돌려주지 않는다).
3. 메인은 렌더러가 보낸 입력을 계약의 Zod 스키마로 파싱한 뒤에만 서버로 보낸다.
4. 오류는 평범한 데이터로 IPC를 건너고 렌더러에서 `ORPCError`로 다시 만든다. 예상하지 못한 오류의 메시지·cause·stack은 렌더러로 보내지 않는다.
5. 리프레시 토큰은 OS 암호화(`safeStorage`)로 사용자만 읽을 수 있는 파일에 저장한다. OS 암호화를 쓸 수 없으면 평문으로 쓰지 않고 메모리에만 둔다. 토큰은 그것을 발급한 서버에만 돌려준다.
6. 창은 번들된 앱 페이지(운영)나 개발 서버 origin(개발)만 연다.

## 시나리오

| ID      | 전제 / 행동                                                       | 결과                                                                                                          |
| ------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| DESK-1  | 렌더러가 `rpc`로 부를 수 있는 절차 목록을 계약과 비교한다         | 세션 절차와 스트림을 뺀 절차와 정확히 같다                                                                    |
| DESK-2  | 렌더러가 허용된 절차를 부른다                                     | 메인이 계약으로 파싱한 입력을 서버로 보내고, 브리지가 점 경로와 입력을 넘겨 결과 데이터를 돌려받는다          |
| DESK-3  | 렌더러가 틀린 입력을 보낸다(일반 절차, 가입)                      | 네트워크에 닿기 전에 `BAD_REQUEST`로 거부된다                                                                 |
| DESK-4  | 입력이 없는 절차에 렌더러가 값을 실어 보낸다                      | 그 값은 서버로 전달되지 않는다                                                                                |
| DESK-5  | 서버가 타입 있는 오류를 돌려준다                                  | code·status·message·data를 그대로 가진 `ORPCError`가 렌더러에서 다시 던져진다                                 |
| DESK-6  | 메인에서 예상하지 못한 오류가 나거나 IPC 페이로드가 깨져 있다     | 렌더러는 메시지·cause·stack 없이 내부 오류만 받는다                                                           |
| DESK-7  | 서버에 연결하지 못한다                                            | `SERVICE_UNAVAILABLE`로 보고된다                                                                              |
| DESK-8  | 성공과 실패 결과가 IPC를 건넌다                                   | structured clone을 거쳐도 깨지지 않는 결과 봉투로 전달된다                                                    |
| DESK-9  | 렌더러가 로그인한다                                               | 메인이 계약으로 입력을 파싱해 로그인하고 사용자만 돌려준다                                                    |
| DESK-10 | 앱이 세션을 복원한다(실행 중 화면 새로고침, 앱 시작, 로그아웃 뒤) | 살아 있는 세션이 있으면 토큰을 다시 회전하지 않고, 시작할 때는 저장된 토큰으로 복원하며, 로그아웃 뒤엔 `null` |
| DESK-11 | 리프레시 토큰을 저장하고 다시 시작한다                            | 암호화된 사용자 전용 파일에서 다시 읽힌다. 회전하면 바뀌고, 로그아웃하면 파일이 지워진다. 없으면 `null`       |
| DESK-12 | OS 암호화를 쓸 수 없거나 파일을 복호화할 수 없다                  | 토큰은 메모리에만 두고, 전에 저장한 파일과 복호화할 수 없는 파일은 지운다                                     |
| DESK-13 | 다른 서버 주소로 앱을 띄운다                                      | 이전 서버에 발급된 토큰을 새 서버에 보내지 않는다                                                             |
| DESK-14 | 창이 어떤 URL로 이동하려 한다                                     | 운영에서는 번들된 페이지, 개발에서는 개발 서버 origin만 허용하고 URL이 아닌 값은 거부한다                     |
| DESK-15 | API 주소를 정한다                                                 | 기본은 로컬 서버이고, `STARTER_API_URL`이 http(s) URL일 때만 그 값을 쓴다. 다른 스킴은 거부한다               |

## 계약

새 절차는 없다. 브리지(`window.desktop`)의 메서드와 IPC 채널은 `apps/desktop/src/shared/ipc.ts`에 있다.
