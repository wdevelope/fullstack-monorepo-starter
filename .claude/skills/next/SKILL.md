# Next (다음 작업)

할 일은 `docs/plans/00-작업목록.md` 한 곳에 모은다. 이 스킬은 "무엇을 할지"만 고른다. "어떻게 할지"는 `spec` → `implement` → `commit` 스킬이 맡는다.

## 목록 형식

```markdown
## 할 일

- [~] 기능 · 글 북마크 → [명세](../specs/bookmarks.md)
- [ ] 버그 · 알림 읽음 처리 실패가 조용히 묻힘 → `apps/web/src/routes/notifications.tsx`
- [ ] 확인 · 모바일 알림함 실기기 확인 (대기: iOS 기기)

## 완료

- [x] 2026-11-25 · 기능 · 글 북마크 → 커밋 `abc1234`
```

- 위에 있을수록 먼저 한다. 한 줄에 한 항목이고, 자세한 내용은 링크한 문서에 둔다.
- 상태 `[ ]` 할 일, `[~]` 진행 중, `[x]` 완료. 종류: 기능, 리팩토링, 버그, 확인, 운영.
- 지금 할 수 없는 항목은 줄 끝에 `(대기: 이유)`를 붙인다.
- 목록을 고치는 데는 승인이 필요 없다. 순서(우선순위)는 사용자가 요청할 때만 바꾼다.

## 사용자의 말과 하는 일

| 사용자의 말                     | 하는 일                                                                                |
| ------------------------------- | -------------------------------------------------------------------------------------- |
| "남은 작업 뭐야?", "해야 할 일" | 목록을 읽고 진행 중, 다음 할 일, 대기 중(이유 포함)을 요약한다. 아무것도 고치지 않는다 |
| "다음 진행해", "이어서 해"      | 아래 "진행하기"대로 한 항목만 끝까지 한다                                              |
| "나중에 하자", "목록에 넣어 둬" | `- [ ] 종류 · 제목 → 링크` 한 줄을 `## 할 일` 맨 아래에 더한다. 지금 하지 않는다       |

## 진행하기

1. **고르기**: 진행 중(`[~]`) 항목이 있으면 그것을 잇는다. 없으면 대기가 아닌 첫 `[ ]` 항목을 고른다.
2. **알리기**: 고른 항목과 할 일을 2~3줄로 알리고, 그 줄을 `[~]`로 바꾼 뒤 진행한다. 목록에 있는 항목은 사용자가 이미 정한 일이므로 "다음 진행해"가 곧 진행 요청이다. 단, 새 기능의 명세 승인은 따로 받는다.
3. **진행**: `spec` → `implement` → `commit` 순서로 한다.
   - 새 기능이거나 해석이 여럿이면 `spec` 스킬의 승인 규칙대로 명세를 먼저 승인받는다.
   - 결정이 필요하면 멈추고 묻는다. 정한 결정은 `docs/DECISIONS.md`에 새 번호로 적는다.
   - 한 번에 끝내기에 크면 하위 항목으로 나눠 첫 하위 항목만 하고, 나머지는 원래 자리에 차례로 적는다.
   - 사용자만 할 수 있는 일(실기기, 외부 콘솔, 비밀값 입력, 업무 판단)은 대신 하지 않는다. 남은 일과 확인 방법을 정리해 알린다.
4. **끝내기**: 그 줄을 `## 완료` 맨 위로 옮겨 `[x] YYYY-MM-DD · 종류 · 제목 → 결과(커밋)`로 바꾼다. 완료 절은 최근 열 줄 정도만 남긴다.
5. **범위 밖 발견**: 작업 중 발견한 범위 밖 일은 목록 맨 아래에 한 줄로 더하고 보고에 적는다. 지금 고치지 않는다.
6. **멈추기**: 한 항목이 끝나면 멈춘다. 다음 항목은 사용자가 다시 말할 때 시작한다.
